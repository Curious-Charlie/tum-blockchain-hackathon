## 0. 一句话

**雇一个 AI agent 帮你在条件满足时付款。它造不了假（合约会验证 API3 签名数据），没干成也收不到钱（Cardano 上的 x402 付款只在成功后才结算）。**

英文 tagline: *"Don't trust your agent. Verify it."*

## 1. 新手必懂的 8 个概念

| 概念 | 类比 | 在我们项目里 |
|---|---|---|
| **区块链 / 测试网** | 一个公开的、谁都改不了的账本。测试网 = 用"玩具钱"的练习账本 | 用两条测试网: **Cardano preprod**（收 agent 的服务费）和 **Base Sepolia**（以太坊系，放合约） |
| **钱包、助记词、地址** | 助记词（24 个单词）= 保险箱的万能密码；地址 = 银行账号，可以公开 | 我已经生成了 3 个钱包，助记词和私钥只存在 `.env` 文件里（不会进 git） |
| **交易 & tx hash** | 一次转账；tx hash = 回执单号，任何人都能在区块浏览器上查 | 提交时要附上 tx hash 作为证据 |
| **测试币** | 玩具钱，免费领 | tADA（Cardano 测试币）、tUSDM（测试美元稳定币）、Base Sepolia ETH（付 gas 手续费）、aUSD（API3 的测试美元） |
| **智能合约** | 一台放在链上的自动售货机：钱放进去，只按写死的规则吐出来，谁也改不了规则 | 我们的合约锁住付款资金，只有数据证明条件成立时才放款 |
| **Oracle 问题 & API3 签名数据** | 合约上不了网。总得有人把"现在汇率是多少"带上链，但带数据的人可能撒谎。API3 的做法：数据源（Airnode）给每条数据**签名**，像盖了防伪章的公证书，改一个数字章就对不上 | agent 把签名数据交给合约，合约自己验章，验不过直接拒绝 |
| **x402** | HTTP 里一个沉睡多年的状态码 "402 Payment Required"。服务端说"付 2 tADA 给我"，客户端签一张付款单再请求一次，像 API 的自动售货机 | Lena 付给 agent 的服务费走 x402 |
| **Facilitator** | x402 里的"收银员"：检查付款单是否有效，再把它提交上链 | 我们自己在服务里跑一个，查链上数据用 Blockfrost |

一个关键细节（我已经在 SDK 源码里确认过）：**x402 的付款单是"签好但先不上链"的。** 服务端先检查付款单，然后去干活：干成了才把付款单提交上链，干砸了（返回错误）付款单就作废，一分钱都不扣。这就是"不成功不收费"，而且是协议自带的。

## 3. 产品设计

### 3.1 场景（推荐，待确认）

> **Lena 在慕尼黑开了一家小咖啡烘焙店，从哥伦比亚的供应商 Café Verde 进咖啡豆。发票是欧元（€1,000），但她手上的钱是美元稳定币。**
> 她希望: "等 EUR/USD 跌到 1.11 以下（欧元便宜时）再付这张发票，11 月 15 日前有效。"
> 她不想每天盯着汇率，于是雇一个 agent 帮她盯盘、到点执行。

**为什么选这个场景:**
- 中小企业跨境付款和汇率换算是真实痛点，评委（慕尼黑、欧洲）一听就懂 → API3 评分里"真实用例"占 40%
- **签名数据直接决定付多少钱**: 付款金额 = €1,000 × 签名的 EUR/USD 汇率。伪造汇率 = 少付供应商或多扣 Lena 的钱 → API3 的"签名数据必不可少"占 30%
- 数据源是 Nodary EUR/USD，**免费、不限量、实时更新**，和官方 starter 的代码路径完全一样，风险最低
- 备选: 同一套引擎换个数据源就能变成"ETH 跌破某个价位时付款"，或者"航班延误理赔"

### 3.2 角色

| 角色 | 是谁 | 用的钱包 |
|---|---|---|
| **Lena**（客户） | 店主，以及替她干活的"财务 agent" | Cardano 买方钱包（付服务费）+ EVM 钱包（存入付款预算） |
| **Keeper agent**（我们的产品） | 帮人盯条件、到点执行付款的 AI agent | Cardano 卖方钱包（收服务费）+ EVM 钱包（付执行交易的 gas） |
| **Café Verde**（收款方） | 供应商 | 一个 EVM 地址 |
| **Nodary Airnode**（数据源） | 给汇率签名的 API3 节点 | — |

### 3.3 完整流程

```
① Lena 用一句话下指令（AI 的作用）
   "Pay Café Verde's invoice #42, €1,000, when EUR/USD drops below 1.11, before Nov 15"
        │  Claude 把这句话解析成结构化订单: {收款方, €1000, 汇率上限 1.11, 截止日期}
        ▼
② Lena 把预算（比如 1,150 美元稳定币）存进合约 —— 钱锁在合约里，agent 碰不到
        ▼
③ 循环（自动，无人操作）:
   Lena 的财务 agent 每分钟问一次 Keeper:
   "订单 #42 能执行了吗？" + 附一张 2 tADA 的 x402 付款单（签了，但先不上链）
        │
        ▼
   Keeper 从 AirnodeHub 取一条签名的 EUR/USD 汇率
        │
        ├── 汇率还 ≥ 1.11 → 回复"还没到"(HTTP 409) → 付款单作废，Lena 一分钱没花
        │
        └── 汇率 < 1.11 → Keeper 把签名数据交给合约
                │
                ▼
            合约自己检查（API3 赛道的核心）:
              ✓ 签名者是 Nodary 吗？      ✓ 是 EUR/USD 这个请求吗？
              ✓ 数据够新吗（5 分钟内）？    ✓ 订单还没执行过吗？
              ✓ 汇率真的 < 1.11 吗？
                │
                ▼
            付 €1000 × 汇率 美元给 Café Verde，剩下的退回 Lena
                │
                ▼
   Keeper 回复成功(200) + 链上交易回执 → x402 付款单这时才上链 → Keeper 收到 2 tADA
```

### 3.4 两个信任问题，各由一条链解决

| 担心 | 解决办法 | 对应赛道 |
|---|---|---|
| agent 会不会伪造汇率乱执行？ | 合约自己验 API3 签名，篡改、过期、错请求、错签名者都会被拒绝 | API3（正好就是 tamper test） |
| agent 会不会卷钱跑？ | 钱锁在合约里，收款方地址写死，agent 只能触发执行，转不走钱 | API3 / 合约设计 |
| agent 没干成也收钱？ | x402 付款单只在执行成功后才结算 | **Cardano**（评委明确要的 "pay only for work that passed a check"） |
| agent 掉线了怎么办？ | `execute` 谁都能调用，安全性来自签名而不是来自"是谁调的"。过了截止日期 Lena 可以取回预算 | 两者 |

**AI 在哪里？** 原则是 **"AI 负责理解，合约负责执行"**。Claude 把自然语言解析成订单、解释每一步发生了什么、（加分项）在 AirnodeHub 目录里自己选数据源。**是否付款永远由合约根据签名数据决定，不由 LLM 决定**。这是一个值得在 pitch 里讲的设计点。

## 4. 技术架构

```
┌──────────────── Base Sepolia (EVM 测试网) ────────────────┐
│  InvoiceEscrow.sol (api3/contracts/)                      │
│   createOrder()  Lena 存预算、设条件                         │
│   execute()      验签名 → 查条件 → 付款给收款方 → 退余额      │
│   refund()       过期后 Lena 取回预算                        │
│  + 演示用美元稳定币 (DemoUSD, 谁都能铸币的 ERC20)              │
└───────────────────────────▲───────────────────────────────┘
                            │ viem (JS 库，发 EVM 交易)
┌──────────── Keeper agent 服务 (cardano/, Node + TS) ───────┐
│  POST /orders/:id/execute   x402 收费端点（2 tADA，成功才结算） │
│  POST /orders/draft         Claude: 自然语言 → 订单           │
│  AirnodeHub 客户端           取签名的 EUR/USD                 │
│  内置 x402 facilitator       用 Blockfrost 查 Cardano preprod  │
│  GET /                      演示用网页 dashboard              │
└───────────────────────────▲───────────────────────────────┘
                            │ x402 (HTTP 402 + Cardano 付款单)
┌──────────── Lena 的财务 agent（cardano/ 里的脚本）────────────┐
│  定时调用 Keeper，带 tADA 付款单；有消费上限（每次最多 5 tADA） │
└────────────────────────────────────────────────────────────┘
```

**为什么用两条链？** Cardano 是 agent 收服务费的支付通道（x402、Masumi 都是 Cardano 官方力推的 agent 支付工具）；被管理的资金和验签合约放在 EVM 上，因为 API3 的签名格式（secp256k1 + keccak256）和官方 starter 都是为 EVM 准备的。agent 跨链工作本来就很现实。

**合约用的稳定币**: aUSD faucet 每个账户总共只能领 10 个，所以合约里的付款用我们自己部署的"演示美元"（金额可以随便定）。aUSD 只用在 x402 购买数据（API3 加分项）。

## 8. 评委可能问的问题（你要能答）

- **为什么用两条链？** 见第 4 节: Cardano 是 agent 的支付通道，EVM 放验签合约和资金。
- **agent 能作弊吗？** 伪造不了数据（签名）、转不走钱（收款方写死）、不能重复执行（合约有记录）、没成功收不到钱（x402）。
- **Lena 能赖账吗？** 理论上她可以在"Keeper 干完活"和"付款上链"之间抢先花掉同一笔钱（双花），这是 x402 先验证后结算的已知限制。单次金额小，所以风险也小；完整的解法是 Masumi escrow（先锁钱），这是我们的 roadmap。**诚实说出局限，评委会加分。**
- **签名证明了什么？** 只证明"这个数是 Nodary 签的、没被改过"，不证明它在现实中是真的，所以仍然要信任数据源本身。（这是 API3 文档里的原话，评委会喜欢听你讲清楚。）
- **挑数据作弊？** 提交者可以在有效期内挑一个对自己有利的汇率提交。缓解办法: 新鲜度窗口很短（5 分钟）。
- **Keeper 挂了怎么办？** 任何人都能用有效的签名数据调用 `execute`；过了截止日期 Lena 取回预算。
